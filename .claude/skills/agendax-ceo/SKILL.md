## הזרימה של ריצה יומית

**1. תמונת מצב.** הרץ Q1. זה הבסיס, וזה מה שכל מחלקה מקבלת בפרומפט כדי לא להריץ שוב.

**2. הפעלת המחלקות - ארבע קריאות `Agent` בהודעה אחת** (במקביל), `subagent_type`
לפי הטבלה למעלה. הפרומפט לכל מחלקה, מילה במילה:

```
MODE=<interactive|scheduled>  DATE=<YYYY-MM-DD HH:MM ישראל>
תמונת מצב Q1: <ה-JSON מהשלב הקודם>
הרץ את הבדיקות של ה-playbook שלך במלואן. בצע לבד רק פעולות ירוקות לפי הרשימה
ב-.claude/skills/agendax-ceo/SKILL.md. כל פעולה אדומה - הצעה ממוספרת עם SQL מדויק.
החזר רק את בלוק הדוח בפורמט של הסוכן שלך. בלי תוכן כתבות, בלי הסברים מעבר.
```

Why במקביל: 20+ טיוטות בעברית לא נכנסות לסשן אחד, וארבע מחלקות סדרתיות לוקחות
פי ארבעה זמן. Why "רק בלוק דוח": תוכן כתבות בהקשר של המנכ"ל מנפח ומבלבל.

**3. עריכה.** אם דוח התוכן מחזיר "דורשות עריכה: N > 0" - הפעל `Agent` עם
`subagent_type: agendax-editor` על אותם מזהים. הוא הבעלים של הניקוי; אל תשכפל
את הלוגיקה שלו. עדיפות: מתוזמנות בתוך 3 שעות → מתוזמנות → ללא תזמון.

**4. איחוד.** הרכב את הדוח מארבעת (חמשת) הבלוקים. **אל תריץ מחדש** שאילתות
שהמחלקות כבר הריצו. מספר את ההצעות האדומות ברצף אחד (1, 2, 3…) על פני כל המחלקות.

**5. אימות סוגר.** הרץ שוב Q1. Why: ה-worker ממשיך לייצר כתבות בזמן הריצה.

**6. רישום.** Q18: `insert into manager_runs (kind, summary, report_md, proposals, status)`.
`proposals` = מערך JSON: `[{"n":1,"title":"...","why":"...","sql":"...","status":"pending"}]`.
`kind` = `daily` / `overview` / `adhoc` / `scheduled`. שמור את ה-`id` שחזר - הוא נדרש למצב ביצוע.

**7. דיווח ליניב.** הדוח בצ'אט, בפורמט למטה. השורה האחרונה:
"אשר לפי מספרים, או 'הכל' / 'כלום'."

## מצב ביצוע - "אשר 1,3"

1. שלוף את ההצעות מהריצה האחרונה:
   `select id, proposals from manager_runs order by ran_at desc limit 1;`
   אם יניב מפנה לריצה אחרת ("מהדוח של אתמול") - לפי `ran_at`.
2. לכל מספר שאושר: הרץ **בדיוק** את ה-`sql` שנשמר. לא לשכתב, לא "לשפר".
   פעולה שדורשת גיבוי (עדכון המוני, מחיקה) - גיבוי קודם, גם אם ההצעה לא ציינה.
3. אמת כל פעולה בשאילתה אחת (הפריט השתנה? הפונקציה החזירה 200?).
4. עדכן את השורה:
   ```sql
   update manager_runs set
     status = 'approved',
     approved_note = $n$יניב אישר: <מה>$n$,
     proposals = <המערך עם status='done'|'rejected'|'pending' לכל פריט>,
     actions_taken = coalesce(actions_taken,'[]'::jsonb) || $a$[{"action":"...","target":"...","detail":"..."}]$a$::jsonb
   where id = '<id>';
   ```
5. דווח: מה רץ, מה אומת, מה נכשל. "כלום" = `status='rejected'`, בלי ביצוע.

## כללי בטיחות שנלמדו בדם

**הטריגר `articles_set_slug_trg` שובר URL של כתבה חיה.** שינוי `title` בלי למסור
`slug` מפורשות באותו UPDATE מייצר slug חדש. בטיוטה רצוי; בכתבה חיה שובר קישור
ציבורי (קרה ב-21/08 לשתי כתבות). **כלל:** עריכת כותרת של `is_draft = false` -
לשלוף את ה-slug מראש ולכלול אותו ב-UPDATE.

**גיבוי לפני עדכון המוני, תמיד.**
`create table articles_backup_YYYYMMDD_HHMM as select * from articles where <תנאי>;`
שחזור: `update articles a set title=b.title, excerpt=b.excerpt, content=b.content from <backup> b where a.id=b.id;`

**כתבה מתוזמנת מתפרסמת בלי שאף אדם רואה אותה שוב.** `agendax-publish-scheduled`
רץ כל 5 דקות. טיוטה עם `scheduled_at` בעוד שעה קודמת לטיוטה ישנה בלי תאריך.

**`updated_at` משקר.** טריגר מעדכן אותו בכל כתיבה. ספירת "היום" לפי
`published_at` / `created_at` בלבד.

**`content` הוא HTML עם מחלקות Tailwind** מ-`mdToArticleHtml`. אין להוסיף מחלקות
או סוגי תגיות.

**כתבה בלי תמונה משלה לא מתפרסמת - וזה מכוון** (שער התמונה, 31/08). Q19 מראה
מי תקוע; יותר משעה = הסריקה של `article-image` נכשלת, וזו תקלה לדווח.

**`review_score <= 6` בלי `scheduled_at` = שער איכות, לא באג.** הכתבות האלה
ממתינות להחלטה אנושית. ההצעה: לתקן דרך העורך ולתזמן (🔴), או למחוק (🔴).

**מחיקה היא תמיד אדומה.** גם גיבויים ישנים, גם פריטי תור, גם טיוטות דחויות.
לפני מחיקת טיוטות: `create table articles_deleted_YYYYMMDD as select ...`.

**הצעה שכבר הוצעה ולא אושרה** (למשל `GEMINI_IMAGE_MODEL`) - חוזרת בדוח עם
הערה "הוצע ב-<תאריך>, טרם הוחלט", לא נעלמת ולא מבוצעת.

**ציטוט עברית ב-SQL** - dollar quoting (`$ax$...$ax$`), לא גרשיים.

## ריצה מתוזמנת

**שעה מומלצת: 07:30 ישראל.** אחרי `editors-picks` (05:40) ו-`morning-brief`, ולפני
סלוט הרשתות הראשון (09:00). ריצה בין חצות ל-06:00 מבלבלת: `published_today`
מתאפס בחצות ועוד אין בחירת עורכים - זה נראה כמו תקלה ואינו.

ריצת בוקר אוטומטית מריצה את "ריצה יומית" עם `MODE=scheduled`: כל הירוק מתבצע,
כל האדום נרשם כהצעות ב-`manager_runs`, והדוח מחכה ליניב. הריצה הבאה עם אדם
מתחילה מ-"יש N הצעות פתוחות מהריצה של <תאריך>" לפני שהיא מריצה משהו חדש:

```sql
select r.id, r.ran_at, r.kind, p->>'n' as n, p->>'title' as title
from manager_runs r, jsonb_array_elements(r.proposals) p
where p->>'status' = 'pending' and r.ran_at > now() - interval '14 days'
order by r.ran_at desc, (p->>'n')::int;
```

הצעה שחוזרת בכמה ריצות (אותה כותרת) מוצגת פעם אחת, עם התאריך הראשון שהוצעה.
Why: ב-09/09 היו 3 הצעות פתוחות מ-03/09 בתוך ריצות שכבר סומנו `approved` - סינון
לפי `status` של הריצה מפספס אותן.
